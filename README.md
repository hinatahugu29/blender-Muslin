# Cloth MD

Blender 用のクロスシミュレーションアドオン。Marvelous Designer のような
**パターンを作って縫い合わせる**衣服制作ワークフローを目指しています。

物理コアは Rust (XPBD) で実装し、PyO3 経由で Blender の Python から呼び出します。

## 現在できること

- **クロスシミュレーション** — XPBD による伸び/曲げ制約、面積ベースの質量分布、
  風(面圧として実装するので生地が重いほどなびきにくい)、減衰、ピン留め
- **コリジョン** — 人体などのメッシュとの衝突(BVH)、自己衝突(空間ハッシュ)、
  床面、摩擦。モディファイアやアーマチュアで変形した状態に追従します
- **縫製** — パターンピースの作成、エッジ選択によるシーム定義、
  弧長ベースの対応付け(頂点数が違う辺同士も縫えます)、縫い線のビューポート表示
- **ベイク** — ディスクへのキャッシュ書き出し、シェイプキーへの変換

## インストール

1. `dist/cloth_md.zip` を用意する(無ければ下記のビルド手順で作る)
2. Blender の Preferences > Add-ons > Install... から zip を選ぶ
3. "Cloth MD" を有効化する
4. 3Dビューの N パネルに "Cloth MD" タブが出る

### 更新するときの注意(Windows)

**必ず Blender を終了してから、古いバージョンを削除してください。**

Windows はロード中の DLL を削除できません。Blender を起動したまま削除・再インストール
すると `cloth_core.pyd` だけが消せず、Blender はアドオンフォルダを
`.~stale~0001` にリネームして退避します。**結果として `.py` だけが消え、
アドオンが壊れた状態になります**(UI に Debug パネルの残骸だけが出る等)。

そうなった場合の復旧:

1. Blender を完全に終了する
2. `%APPDATA%\Blender Foundation\Blender\<版>\scripts\addons\.~stale~*` を削除する
3. Blender を起動して zip を入れ直し、有効化したらもう一度再起動する

`.pyd` が新しくなったかは Debug > `Test Rust Core` のコンソール出力
(`core_version`)で確認できます。

動作確認環境: Blender 5.2 LTS / Windows。
拡張モジュールは abi3-py311 でビルドしているため Python 3.11 以降で動きます。

## 使い方

### 布を垂らす

1. 平面メッシュを用意し、編集モードで細分化する
2. 固定したい頂点を頂点グループに入れ、Pinning で指定する
3. `Start Simulation` を押してタイムラインを再生する

### 人体に着せる

1. Collision パネルで `Collider` に人体メッシュを指定する
2. `Thickness` を布のエッジ長より小さい値にする
3. 動く人体に着せる場合は `Animated Collider` を有効にする

### 縫い合わせる

1. Pattern パネルでサイズと解像度を決めて `Add Pattern Piece`(複数作る)
2. 縫いたいピースを選択して `Join Pattern Pieces`
   （**縫い目は同一オブジェクト内でしか作れません**）
3. 編集モードで、縫い合わせたい**2本のエッジ列を同時に選択**して `Add Seam From Selection`
4. ビューポートに出る縫い線が交差していたら、リストの ⇔ ボタンで向きを反転する
5. `Start Simulation` → 再生すると `Seam Close Frames` かけて縫い合わさる

### ベイクする

`Bake to Disk` でシーンのフレーム範囲を計算し、ディスクに保存します。
`.blend` を閉じても残り、スクラブが即座に効きます。
`Convert to Shape Keys` を使うと、アドオン無しで再生できる形になります。

## ビルド

必要なもの: Rust (rustup/cargo)、maturin、Python 3.11 以降

```bash
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

Rust の単体テストを実行し、`maturin build` で wheel を作り、
`cloth_core.pyd` を `addon/cloth_md/` に配置します。

配布用 zip を作る:

```bash
powershell -ExecutionPolicy Bypass -File scripts/package_zip.ps1
```

## 検証

物理コアは pyo3 に依存しない構造にしてあるため、**Blender を起動せずに検証できます**。

```bash
powershell -ExecutionPolicy Bypass -File scripts/verify_core.ps1 -Bench
```

ビルド済みの `.pyd` を Python から直接叩き、自由落下が解析解に一致するか、
布が球を貫通しないか、縫い目が閉じるか等を検査します(`--bench` で性能計測も)。

Rust 側の単体テストのみを走らせる場合:

```bash
cargo test --no-default-features --release --manifest-path rust/cloth_core/Cargo.toml
```

## パラメータの決め方

4,225頂点(65x65、エッジ長 0.031m)を球に被せた実測にもとづく指針です。

### Self Thickness はエッジ長で決まる

自己衝突は、**制約で結ばれていない**頂点対が `Self Thickness` より近いと押し離します。
四角形グリッドで制約が無い最短の対は**斜め方向(エッジ長 x 1.41)**です。
ここを超える値にすると、**平らな布の状態ですでに斜めの頂点対が押し合い**、
伸び制約との綱引きで規則的な座屈が出ます。

| Self Thickness | 伸び誤差 |
|---|---|
| 自己衝突なし | 0.0148 |
| 0.05 (斜め 0.044 を超過) | **0.0458** |
| 0.015 | 0.0173 |
| 0.010 | 0.0158 |

**エッジ長の 0.3〜0.5倍**を目安にしてください。
なお**メッシュを細かくすると許容値はさらに小さくなります**(エッジ長が縮むため)。
自己衝突が破綻したときに細分化するのは逆効果です。

### 収束は Iterations より Substeps

**衝突の解決はサブステップごとに1回**で、制約反復ループの外側にあります。
そのため **Iterations を増やしても貫通は改善しません**(布が硬くなるだけ)。
貫通と伸びの両方に効くのは Substeps です。

上端をピン留めした布を静定させ、内側の求解回数(iterations x substeps)を
揃えて比べた結果:

| 内側の回数 | iter x subs | 定常誤差 | ms/frame |
|---|---|---|---|
| 40 | 20 x 2 | 0.0240 | 6.5 |
| 40 | 10 x 4 | 0.0122 | 7.1 |
| 40 | 5 x 8 | 0.0061 | 6.8 |
| 32 | 2 x 16 | 0.0039 | 6.5 |
| 32 | **1 x 32** | **0.0019** | 6.8 |

**同じコストで、サブステップに寄せるほど正確**になります(1x32 は 20x2 の
12.6倍正確)。これは Macklin et al., *Small Steps in Physics Simulation*
(SCA 2019) の主張と一致します。

ただし**これは衝突が無い場合**です。衝突を有効にするとサブステップ毎に
衝突解決が走るため、コストが跳ね上がります。球コライダーありで測ると:

| iter x subs | ms/frame | 定常誤差 |
|---|---|---|
| **10 x 4 (既定)** | **11.1** | **0.0106** |
| 5 x 4 | 7.5 | 0.0205 |
| 2 x 16 | 31.0 | 0.0029 |
| 1 x 32 | 47.4 | 0.0012 |

**既定より「安くて正確」な設定は見つかりませんでした。**
精度が要るときに Substeps を上げる、という使い分けになります。

### Substeps は「布の揺れの持ち」にも効く

伸び誤差には現れませんが、Substeps が少ないと**人工的な減衰**が入ります。
`Damping` を 0 にしても布の揺れが不自然に早く止まる現象です。

片端を固定した布を振らせ、1往復あたりの振幅の保持率を測った結果:

| iter x subs | 内側の回数 | 振幅保持率 |
|---|---|---|
| 1 x 4 | 4 | 0.9151 |
| **10 x 4 (既定)** | 40 | **0.9688** |
| 2 x 4 | 8 | 0.9871 |
| **1 x 16** | 16 | **0.9999** |
| 1 x 32 | 32 | 0.9999 |

既定では**1往復ごとに振幅の 3.1% が失われます**。`1 x 16` は内側の求解が
2.5分の1なのに、人工減衰は 300分の1です。

**旗やカーテンのように揺れ続けてほしいものは Substeps を 16 に、
Iterations を 1〜2 に下げてください。** 着せ替えのように最終的な
ドレープが目的なら既定のままで構いません。

### Cache Collision Search

コライダーの探索をフレーム先頭で1回だけ行い、サブステップ間で使い回します。
結果は変わりません(頂点位置がビット単位で一致することをテストで確認)。

| Substeps | 効果 |
|---|---|
| 4 以下 | わずかに遅い(0.93〜0.99倍) |
| 8 | 1.1〜1.2倍 |
| 16〜32 | 1.2〜1.5倍 |

**Substeps を上げるときだけ有効にしてください。** 自己衝突には適用されません
(計測の結果、自己衝突ではハッシュ再構築は全体の11%に過ぎず、探索範囲を広げると
候補が実接触の1000倍以上に膨れて逆効果でした)。

### Post-Collision

衝突の押し出しはサブステップ内の制約ループの後に走るため、押し広げられた分を
伸び制約が回収できません。`Post-Collision` はその後始末を行う回数です。

| Post-Collision | 伸び誤差(Self Th 0.05) | ms/frame |
|---|---|---|
| 0 | 0.0458 | 20.3 |
| 2 (既定) | 0.0239 | 21.6 |
| 8 | 0.0116 | 23.3 |

貫通を増やさずに効きます(上記の計測では球からの距離はむしろ改善)。
厚みを大きく取りたいときに上げてください。

## 性能の目安

CPU シングルスレッド、iterations=10 / substeps=4:

| 頂点数 | ms/frame |
|--------|----------|
| 1,681 | 2.4 |
| 6,561 | 8.2 |
| 14,641 | 18.7 |

自己衝突を足したときの追加コスト(球コライダーあり、繰り返し5回の最小値):

| 頂点数 | 自己衝突なし | 自己衝突あり | 追加分 |
|--------|------------|------------|--------|
| 8,281 | 20.3 ms | 27.9 ms | +7.6 ms |
| 14,641 | 23.1 ms | 38.0 ms | +15.0 ms |

以前は 14,641頂点で +41.3ms かかっていた。空間ハッシュのキー
`(i64, i64, i64)` に標準の SipHash を使っていたのが主因で、
軽量ハッシャ(`GridHasher`)への差し替えと近傍バッファの使い回しで
**追加コストを 64% 削減**した。

この表は Rust コア内部の計測で、Blender との座標受け渡しは含みません。
往復の変換コストは 14,641頂点で約 2.8ms(numpy 化前は約 10ms)です。

## 既知の制約

- 連続衝突判定(CCD)が無いため、高速に動くと貫通することがあります
- 自己衝突は頂点同士の反発のみで、頂点-三角形の貫通は完全には防げません
- 別オブジェクトのパターン同士は縫えません(事前に統合が必要)
- メッシュを編集して頂点番号が変わると縫い目が壊れます(`Validate Seams` で検出可)
- ベースメッシュの頂点を直接書き換えるため、モディファイアスタックとの相性に制約があります
