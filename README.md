# Muslin

Blender 用のクロスシミュレーションアドオン。Marvelous Designer のような
**パターンを作って縫い合わせる**衣服制作ワークフローを目指しています。

物理コアは Rust (XPBD) で実装し、PyO3 経由で Blender の Python から呼び出します。

> **Muslin(モスリン)**とは、本番の生地を裁つ前にパターンを縫って形を確かめる
> 仮縫いの試作のこと。このアドオンがやっていることそのものなので名前にしました。

## 現在できること

- **クロスシミュレーション** — XPBD による伸び制約と曲げ制約、面積ベースの質量分布、
  風(面圧として実装するので生地が重いほどなびきにくい)、減衰、ピン留め
- **生地プリセット** — シフォンからレザーまで7種類。密度は実際の目付(g/m^2)に
  もとづく値です。設定は**布ごと**に持つので、1シーンで生地を作り分けられます
- **コリジョン** — 人体などのメッシュとの衝突(BVH)、自己衝突(空間ハッシュ)、
  床面、摩擦。モディファイアやアーマチュアで変形した状態に追従します
- **縫製** — パターンピースの作成、エッジ選択によるシーム定義、
  弧長ベースの対応付け(頂点数が違う辺同士も縫えます)、縫い線のビューポート表示
- **型紙の確定** — ピースを胴のまわりに曲げて置く前に `Lock Pattern` を押すと、
  平らな形が型紙(布の寸法の基準)として固定されます
- **着せ付け** — `Dress` でタイムラインを進めずに縫って落ち着くまで回し、その形を
  アニメーションの開始姿勢にします(縫い目が閉じていくフレームがアニメーションに入りません)
- **整える** — 着せた後に `Adjust` を押すと、布を左ドラッグでつまんで直せます。
  Enter で保存、Esc で元に戻します(自動では終わりません)
- **型紙と着せた姿勢** — 着せた形を `Save Dressed Pose` で開始姿勢にしても、布の寸法は
  型紙のまま保たれます(着せ直すたびに服が大きくなることがありません)。
  `Restore Pattern` で型紙の形に戻れます
- **ゴム紐** — 辺を選んで `Add Elastic From Selection` を押すと、その辺が縮んで布が寄ります(ウエストや袖口のゴム)
- **重ね着** — 服の Collision パネルで同じ `Group` 名を付けると一緒に解かれ、服どうしが押し合います。`Layer`(0 が内側)で内側の服を優先します
- **型紙から UV** — `Pattern to UV` で、型紙の実寸の比を保った UV を作ります(着せた後も柄がゆがみません)
- **ベイク** — ディスクへのキャッシュ書き出し、シェイプキーへの変換

## インストール

### Blender 4.2 以降(推奨)

Extensions 形式で配布します。Rust 製のモジュールは Python wheel として
同梱されるので、`.pyd` がロックされて更新できない問題が起きません。

1. `dist/muslin-0.5.0.zip` を用意する(無ければ下記のビルド手順で作る)
2. Preferences > Get Extensions > 右上の ∨ > **Install from Disk** から選ぶ
3. 3Dビューの N パネルに "Muslin" タブが出る

### Blender 4.2 より前

従来形式の `dist/muslin.zip` を使います。

1. Preferences > Add-ons > Install... から zip を選ぶ
2. "Muslin" を有効化する

### 更新するときの注意(Windows)

**必ず Blender を終了してから、古いバージョンを削除してください。**

Windows はロード中の DLL を削除できません。Blender を起動したまま削除・再インストール
すると `cloth_core.pyd` だけが消せず、Blender はアドオンフォルダを
`.~stale~0001` にリネームして退避します。**結果として `.py` だけが消え、
アドオンが壊れた状態になります**(UI に Debug パネルの残骸だけが出る等)。

そうなった場合の復旧:

1. Blender を完全に終了する
2. `%APPDATA%\Blender Foundation\Blender\<版>\scripts\addons\.~stale~*` を削除する
3. Blender を起動して zip を入れ直し、有効化したらもう一度再起動する

`.pyd` が新しくなったかは Debug > `Test Rust Core` のコンソール出力
(`core_version`)で確認できます。

動作確認環境: Blender 5.2.1 LTS / Windows。
拡張モジュールは abi3-py311 でビルドしているため Python 3.11 以降で動きます。

**物理コアは Linux / macOS でも CI で毎回テストしています**(`cargo test` と
wheel のビルド + 検証ハーネス)。ただし Blender に入れての動作確認は
Windows でしかしていません。

## サンプル

`samples/` に .blend を3つ用意しています。**開いて `Start Simulation` を押し、
再生するだけ**で結果が見られます。

| ファイル | 内容 |
|---|---|
| `01_drape.blend` | 球に布を被せる。最も基本的な使い方 |
| `02_flag.blend` | 風になびく旗。Substeps を上げて揺れを持続させた例 |
| `03_sewing.blend` | 2枚のパターンを左右で縫って筒にする。パターンを縫い合わせるワークフローの核心 |

手で作った .blend ではなくスクリプトから生成しているので、
アドオンが変わったら作り直せます。

```bash
blender --background --factory-startup --python scripts/make_samples.py
```

## 設定はどこにあるか

**シミュレーションの設定は布(オブジェクト)ごとに持ちます。** Blender 標準の
Cloth モディファイアと同じで、1つのシーンでシルクのブラウスとデニムのパンツを
同居させられます。N パネルの表示は、選択中のメッシュの設定です。

シーン全体で共通なのは次の3つだけです。

- `Use Scene FPS` / `Time Step` — 1フレームが表す時間
- `Show Seams` — 縫い線の表示
- Pattern パネルの `Width` / `Height` / `Resolution` — パターン作成の道具設定

## 使い方

### 布を垂らす

1. 平面メッシュを用意し、編集モードで細分化する
2. 固定したい頂点を頂点グループに入れ、Pinning で指定する
3. `Start Simulation` を押してタイムラインを再生する

### 人体に着せる

1. Collision パネルで `Collider` に人体メッシュを指定する
2. `Fit Thickness to Mesh` を押す(布の細かさに合った厚みが入ります)
3. Fabric で生地を選ぶ
4. 動く人体に着せる場合は `Animated Collider` を有効にする

生地の硬さの違いを出したい場合は、Solver の `Substeps` を 16 以上にしてください
(理由は「パラメータの決め方」を参照)。

### 縫い合わせる

1. Pattern パネルでサイズと解像度を決めて `Add Pattern Piece`(複数作る)
2. 縫いたいピースを選択して `Join Pattern Pieces`
   （**縫い目は同一オブジェクト内でしか作れません**）
3. 編集モードで、縫い合わせたい**2本のエッジ列を同時に選択**して `Add Seam From Selection`
4. ビューポートに出る縫い線が交差していたら、リストの ⇔ ボタンで向きを反転する
5. `Start Simulation` → 再生すると `Seam Close Frames` かけて縫い合わさる

ピースは重ねて配置しても構いません。**`Start Simulation` が開始時点の食い込みを
速度を出さずに解消します**(これが無いと、押し出した距離がそのまま速度になって
布が吹き飛びます)。深く絡んで解消しきれない場合は警告が出ます。

### ベイクする

`Bake to Disk` でシーンのフレーム範囲を計算し、ディスクに保存します。
`.blend` を閉じても残り、スクラブが即座に効きます。
`Convert to Shape Keys` を使うと、アドオン無しで再生できる形になります。

## ビルド

必要なもの: Rust (rustup/cargo)、maturin、Python 3.11 以降

`maturin` は `python -m pip install maturin` で入ります。`build.ps1` は
`maturin` をそのまま呼ぶので、`Scripts` ディレクトリが PATH に必要です。
動作確認したのは maturin 1.15.0 です。

```bash
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

Rust の単体テストを実行し、`maturin build` で wheel を作り、
`cloth_core.pyd` を `addon/muslin/` に配置します。

配布物を作る:

```bash
powershell -ExecutionPolicy Bypass -File scripts/package_extension.ps1
```

Extensions 形式(Blender 4.2 以降)のパッケージを作ります。マニフェストを
Blender 自身に検証させ、**一時領域にインストールして実際に布が落ちるところまで
確かめて**から完成とします(ユーザーの Blender 設定は触りません)。

従来形式が要る場合:

```bash
powershell -ExecutionPolicy Bypass -File scripts/package_zip.ps1
```

### 全プラットフォームぶんをまとめる

`package_extension.ps1` は手元の Windows 用 wheel を1つ入れるだけです。
Linux や macOS の wheel は手元では作れないので、**GitHub Actions の
`Release` ワークフロー**で各 OS が作った wheel を集めて1つの zip にします。

Actions タブから `Release` を手動実行するか、`v` で始まるタグを push します。
`muslin-extension` という成果物に、4プラットフォーム
(windows-x64 / linux-x64 / macos-arm64 / macos-x64)の wheel を同梱した
zip が出ます。

集める部分は [scripts/build_extension.py](scripts/build_extension.py) で、
wheel のファイル名からプラットフォームを判別してマニフェストの
`platforms` / `wheels` を書き換えます。手元でも使えます:

```bash
python scripts/build_extension.py --out dist/muslin.zip path/to/*.whl
```

## パラメータの決め方

4,225頂点(65x65、エッジ長 0.031m)を球に被せた実測にもとづく指針です。

### Self Thickness はエッジ長で決まる

自己衝突は、**制約で結ばれていない**頂点対が `Self Thickness` より近いと押し離します。
四角形グリッドで制約が無い最短の対は**斜め方向(エッジ長 x 1.41)**です。
ここを超える値にすると、**平らな布の状態ですでに斜めの頂点対が押し合い**、
伸び制約との綱引きで規則的な座屈が出ます。

| Self Thickness | 伸び誤差 |
|---|---|
| 自己衝突なし | 0.0148 |
| 0.05 (斜め 0.044 を超過) | **0.0458** |
| 0.015 | 0.0173 |
| 0.010 | 0.0158 |

**エッジ長の 0.3〜0.5倍**を目安にしてください。
なお**メッシュを細かくすると許容値はさらに小さくなります**(エッジ長が縮むため)。
自己衝突が破綻したときに細分化するのは逆効果です。

Collision パネルの **`Fit Thickness to Mesh`** を押すと、メッシュのエッジ長
(中央値・スケール適用後)から `Thickness` と `Self Thickness` を自動で決めます。
過大なまま `Start Simulation` した場合も警告が出ます。

### Catch Fast Motion(高速な交差)

位置だけを見る衝突判定は、**1サブステップの移動量が厚みを超えると布が
素通りします**。抜けない上限速度は式で決まります:

    抜けない上限速度 = Self Thickness x fps x Substeps

`Self Thickness` 0.016 / 60fps / `Substeps` 4 なら 3.84 m/s です。
`Catch Fast Motion`(既定で有効)は、頂点の**前後の位置を結ぶ線分**で
判定して、飛び越えた事実そのものを捕まえます:

| 落下速度 | 切ったとき | 入れたとき |
|---|---|---|
| 3.13 m/s | 素通り 0/225 | 0/225 |
| 4.43 m/s | **225/225 素通り** | **0/225** |
| 6.26 m/s | **225/225 素通り** | **0/225** |
| 12.0 m/s | 1/225 | **0/225** |
| 30.0 m/s | **225/225 素通り** | 26/225 |

**上限が 3.84 m/s から 12 m/s まで伸びます。** 費用は 14,641頂点・
`Substeps` 4 で **+10%**、`Substeps` 16 なら **+1%** 未満です
(`Substeps` が大きいほど1回の移動量が小さく、判定に入る頂点が減るため)。
自己衝突が無効なら一切走りません。

三角形の側は現在位置で見ているので、**布どうしが互いに高速ですれ違う**
場合は取りこぼすことがあります。そこは `Substeps` を上げてください。

### 収束は Iterations より Substeps

**衝突の解決はサブステップごとに1回**で、制約反復ループの外側にあります。
そのため **Iterations を増やしても貫通は改善しません**(布が硬くなるだけ)。
貫通と伸びの両方に効くのは Substeps です。

上端をピン留めした布を静定させ、内側の求解回数(iterations x substeps)を
揃えて比べた結果:

| 内側の回数 | iter x subs | 定常誤差 | ms/frame |
|---|---|---|---|
| 40 | 20 x 2 | 0.0240 | 6.5 |
| 40 | 10 x 4 | 0.0122 | 7.1 |
| 40 | 5 x 8 | 0.0061 | 6.8 |
| 32 | 2 x 16 | 0.0039 | 6.5 |
| 32 | **1 x 32** | **0.0019** | 6.8 |

**同じコストで、サブステップに寄せるほど正確**になります(1x32 は 20x2 の
12.6倍正確)。これは Macklin et al., *Small Steps in Physics Simulation*
(SCA 2019) の主張と一致します。

ただし**これは衝突が無い場合**です。衝突を有効にするとサブステップ毎に
衝突解決が走るため、コストが跳ね上がります。球コライダーありで測ると:

| iter x subs | ms/frame | 定常誤差 |
|---|---|---|
| **10 x 4 (既定)** | **11.1** | **0.0106** |
| 5 x 4 | 7.5 | 0.0205 |
| 2 x 16 | 31.0 | 0.0029 |
| 1 x 32 | 47.4 | 0.0012 |

**既定より「安くて正確」な設定は見つかりませんでした。**
精度が要るときに Substeps を上げる、という使い分けになります。

### 生地の違いを出すには Substeps を上げる

Fabric プリセット(Chiffon / Silk / Knit / Cotton / Wool / Denim / Leather)は
密度・伸び・曲げ・減衰をまとめて設定します。密度は実際の生地の目付
(g/m^2)にもとづく値です。

ただし**曲げ剛性は Substeps に強く依存します**。片持ちの短冊を垂らして
測ると、生地ごとの差は次のように変わります(垂れ比。小さいほど硬い):

| solver 設定 | 最も柔らかい生地 | 最も硬い生地 | 差 |
|---|---|---|---|
| iterations 10 / **substeps 4**(既定) | 0.977 | 0.971 | **0.006** |
| iterations 10 / substeps 16 | 0.977 | 0.913 | 0.064 |
| iterations 20 / **substeps 32** | 0.974 | 0.666 | **0.309** |

**既定の Substeps 4 では、どの生地もほとんど同じように垂れます。**
デニムや革の硬さを出したいなら Substeps を 16 以上にし、あわせて
**`Convergence Boost` を 0.98 にしてください**(次項)。
これは PBD 系の性質で、剛性が反復回数に依存するためです。

### Convergence Boost(収束加速)

Solver の `Convergence Boost` は制約の収束を速めます(Chebyshev 半復法)。
**反復そのものを加速するだけで材質は変えない**ので、硬い生地は硬く、
柔らかい生地は柔らかいまま、どちらも本来の挙動に近づきます。

7種類のプリセットの垂れ比の差(大きいほどプリセットが効いている):

| 設定 | 生地の差 | 最も硬い生地 |
|---|---|---|
| iterations 10 / substeps 4(既定) | 0.017 | 0.986 |
| iterations 20 / substeps 32 | 0.546 | 0.330 |
| **iterations 10 / substeps 32 + Boost 0.98** | **0.643** | **0.275** |
| iterations 20 / substeps 32 + Boost 0.98 | 0.676 | 0.241 |

**Substeps と組み合わせたときに効きます。** コストはフレームあたり 1% 未満
です(内側の求解回数が同じなら 3.04ms → 3.06ms)。

反復数ごとの効き(substeps 32、垂れ比。小さいほど硬い):

| Iterations | Boost 0 | 0.95 | **0.98** |
|---|---|---|---|
| 8 | 0.747 | 0.597 | 0.573 |
| **10** | 0.703 | 0.497 | **0.408** |
| 16 | 0.593 | 0.390 | 0.330 |
| 20 | 0.507 | 0.294 | 0.234 |

**`Iterations` が 5 以下のときは加速されません。** 短い反復で加速すると
行き過ぎて布が反り返る(先端が固定端より上に上がる)ため、構造的に
無効化しています。効かせたいなら `Iterations` を 8 以上にしてください。

**反復数をいくつ上げても安全です。** 加速は 10 反復ごとにリスタートします。
これが無いと外挿が積み上がって布が吹き飛びます(0.4m 角の布が反復40・
ρ0.98 で 12m まで広がった)。`is_finite()` では捕まらない壊れ方なので、
広がりと伸び誤差の両方で縛る回帰テストを入れてあります。

柔らかい生地にも害はありません。球に被せたときの水平の広がりは
`substeps 32` で 0.576、`+ Boost 0.95` で 0.526 と、**むしろよく巻き付きます**。

**推奨は 0.98** です(UI の上限)。既定は 0 (無効) なので、これまでの
シーンの結果は変わりません。

硬い生地を選んだまま Substeps が低いと、`Start Simulation` で警告が出ます。

#### 硬さの上限を決めているのは生地の設定ではありません

`Bending Compliance` を 0(完全剛体)にしても、Substeps が低いと布は垂れきります。
**曲げ制約が収束していない**ためで、生地の設定では超えられない上限があります。

| Substeps | compliance=0(最も硬い設定)での垂れ比 |
|---|---|
| 4(既定) | 1.02 — 垂れきる |
| 8 | 0.95 |
| 16 | 0.89 |
| 32 | 0.70 |

上の表は「その Substeps で作れる最も硬い布」です。既定では **compliance を
どう設定しても垂れ比 1.02〜1.04 の範囲にしかならず**、7種類のプリセットの
差は 0.016 しかありません。どれを選んでも垂れきった状態の近くに張り付く、
ということです。Substeps を上げる以外に硬くする手段はありません。

なお**広い間隔の曲げ制約を足して収束を助ける案は、計測して退けました**
(硬さは出せますが、球に被せたときに布が巻き付かず板になります)。
経緯と数値は [ROADMAP.md](ROADMAP.md) に残しています。

### Substeps は「布の揺れの持ち」にも効く

伸び誤差には現れませんが、Substeps が少ないと**人工的な減衰**が入ります。
`Damping` を 0 にしても布の揺れが不自然に早く止まる現象です。

片端を固定した布を振らせ、1往復あたりの振幅の保持率を測った結果:

| iter x subs | 内側の回数 | 振幅保持率 |
|---|---|---|
| 1 x 4 | 4 | 0.9151 |
| **10 x 4 (既定)** | 40 | **0.9688** |
| 2 x 4 | 8 | 0.9871 |
| **1 x 16** | 16 | **0.9999** |
| 1 x 32 | 32 | 0.9999 |

既定では**1往復ごとに振幅の 3.1% が失われます**。`1 x 16` は内側の求解が
2.5分の1なのに、人工減衰は 300分の1です。

**旗やカーテンのように揺れ続けてほしいものは Substeps を 16 に、
Iterations を 1〜2 に下げてください。** 着せ替えのように最終的な
ドレープが目的なら既定のままで構いません。

### Cache Collision Search

コライダーの探索をフレーム先頭で1回だけ行い、サブステップ間で使い回します。
結果は変わりません(頂点位置がビット単位で一致することをテストで確認)。

| Substeps | 効果 |
|---|---|
| 4 以下 | わずかに遅い(0.93〜0.99倍) |
| 8 | 1.1〜1.2倍 |
| 16〜32 | 1.2〜1.5倍 |

**Substeps を上げるときだけ有効にしてください。** 自己衝突には適用されません
(計測の結果、自己衝突ではハッシュ再構築は全体の11%に過ぎず、探索範囲を広げると
候補が実接触の1000倍以上に膨れて逆効果でした)。

### Post-Collision

衝突の押し出しはサブステップ内の制約ループの後に走るため、押し広げられた分を
伸び制約が回収できません。`Post-Collision` はその後始末を行う回数です。

| Post-Collision | 伸び誤差(Self Th 0.05) | ms/frame |
|---|---|---|
| 0 | 0.0458 | 20.3 |
| 2 (既定) | 0.0239 | 21.6 |
| 8 | 0.0116 | 23.3 |

貫通を増やさずに効きます(上記の計測では球からの距離はむしろ改善)。
厚みを大きく取りたいときに上げてください。

## 性能の目安

制約の求解は1スレッド、コリジョンは並列(4,000頂点以上のとき)。
`iterations 10 / substeps 4`、繰り返し7回の最小値:

| 頂点数 | 制約のみ | + 自己衝突 |
|--------|---------|-----------|
| 1,681 | 2.0 ms | 5.5 ms |
| 4,225 | 5.1 ms | 10.2 ms |
| 14,641 | 18.8 ms | 33.5 ms |

14,641頂点・自己衝突ありで 30 fps 相当です。内訳:

| 内訳 | ms | 割合 |
|------|-----|------|
| 自己衝突 | 14.8 | 44.3% |
| └ 空間ハッシュの再構築 | 10.0 | 29.8% |
| 伸び制約 | 9.4 | 27.9% |
| 曲げ制約 | 6.9 | 20.6% |

**自己衝突が最大の項目です。** 頂点同士の反発だけでは
[頂点の並びがずれた2枚が素通りする](#既知の制約)ため、頂点-三角形の判定を
足しました。三角形を厚みぶん広げて空間ハッシュに入れる処理が重く、
自己衝突なしと比べて 1.8倍になります。**自己衝突を切れば 18.8 ms です。**

ハッシュの作り方で大きく変わります。当初は1三角形が18セルに跨る作りで、
14,641頂点では毎サブステップ 3.7MB を触っていました。その結果、**無関係な
伸び制約と曲げ制約までキャッシュから追い出され**、それぞれ 9.7 → 21.1 ms、
6.6 → 16.7 ms に膨らんでいました。セルを広げ、ハッシュ値を u32 に落とし、
バケット数を減らして 1.4MB まで削ったところ、巻き添えが消えて
全体が 64.9 → 33.5 ms になりました。

計測にあたっての注意:

- **この表は Rust コア内部の時間**で、Blender との座標受け渡しは含みません。
  往復の変換は 14,641頂点で約 2.8ms です
- **曲げ制約の数はメッシュの張り方で変わります**。四角形メッシュなら
  格子線のエッジだけが対象ですが、三角形メッシュでは対角線も対象になり、
  制約数が 1.5倍・曲げのコストが 2.5倍になります
- 同一バイナリ・同一設定でも実行間で 34% のばらつき(二峰性)が出ます。
  最小値を採る、同一実行内で比較する、といった手当てが要ります

## 既知の制約

- 完全な連続衝突判定(CCD)はありません。ただし主な失敗は塞いであります:

  - **コライダー相手**: 対処済み。球を 60 m/s、直径 2cm の棒を 30 m/s で
    通しても布に当たります(サブステップ補間 + 移動量ぶん広げた探索半径)
  - **布どうし**: `Catch Fast Motion`(既定で有効)が前後の位置を結ぶ線分で
    判定します。素の上限は `Self Thickness x fps x Substeps` で、
    厚み 0.016 / 60fps / `Substeps 4` なら 3.84 m/s ですが、**掃過判定で
    12 m/s まで伸びます**。費用は 14,641頂点・`Substeps 4` で +10%

  残っているのは、**布どうしが互いに高速ですれ違う**場合だけです。
  三角形の側は現在位置で見ているためで、そこは `Substeps` を上げてください
- 自己衝突は頂点同士の反発と頂点-三角形の判定まで。エッジ同士の交差は
  見ていませんが、崩落した布で数えると**エッジ同士でしか拾えない違反は
  0.1%**でした(実測は ROADMAP)。既定の `Substeps 4` では潰れた接触が
  残るので、**自己衝突を使うなら Substeps 8 以上**にしてください
- 走行中に厚み以上の深さまで食い込むと、押し出しが速度に変わって弾かれます
  (開始時点の食い込みは `Start Simulation` が自動で解消するので問題ありません)
- 摩擦は速度を減衰させる簡易モデルで、物理的な摩擦係数 μ ではありません。
  `Surface Friction` を 0.7 より下げると、球に落とした布が留まらず滑り落ちます
- 別オブジェクトのパターン同士は縫えません(事前に統合が必要)
- メッシュを編集して頂点番号が変わると縫い目が壊れます。`Start Simulation` 時に警告が出るほか、`Validate Seams` でも検出できます
- ベースメッシュの頂点を直接書き換えるため、モディファイアスタックとの相性に制約があります
- 曲げ剛性が solver の反復数に依存します。既定の `Substeps 4` では生地の違いが
  ほとんど出ません(PBD 系に共通の性質)
