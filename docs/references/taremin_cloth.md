# 先行事例メモ: Taremin Cloth

Muslin と同じ「Rust + PyO3 + XPBD で型紙を縫う Blender アドオン」を先に作っている
プロジェクトから、**知見と概念だけ**を抜き出した記録。コードは取り込んでいない。

- リポジトリ: https://github.com/Taremin/TareminCloth
- 読んだ版: `56f39f0` (2026-09-21)
- 手元の写し: `Reference/TareminCloth/`(git clone。`/Reference/` は .gitignore 済みで、このリポジトリには含めない。更新は `git -C Reference/TareminCloth pull`)
- 読んだもの: `docs/algorithms.md`, `docs/architecture.md`, `docs/related_research.md`,
  主要な WGSL シェーダー、`python/taremin_cloth` の設定とランナー、物理テストの見出し
- ライセンス: Python 部分は GPL-3.0-or-later、Rust コア (`crates/cloth_core`) は Unlicense。
  Muslin は GPL-3 なので、どちらを参考にしても法的な問題はない

**扱い方:** 向こうの結論は向こうの条件(GPU、RX 9070 XT、向こうのテストシーン)で出たもの。

## 1. 相手の全体像(比較の前提)

| | Muslin | Taremin Cloth |
|---|---|---|
| 計算 | CPU(rayon、彩色した色の中だけ並列) | GPU(wgpu / WGSL) |
| 反復 | Jacobi 系 + Chebyshev 加速 | 彩色 Gauss-Seidel(Welsh-Powell)/ Atomic Jacobi 切替 |
| 衝突 | 三角形 BVH、掃過判定 | メッシュ、SDF(プリミティブ / メッシュ / ボーン別)、頂点-三角形 + 辺-辺 + CCD |
| 自己衝突 | 頂点-頂点のみ、空間ハッシュ | 頂点-頂点 + 頂点-三角形 + 辺-辺、ソート済み一様グリッド、候補ペアのキャッシュ |
| 縫製 | エッジ選択でシームを定義、弧長で対応付け、`seam_closure` で rest を 0 へ補間 | 孤立エッジ = 縫い線、`shrink_speed` [m/s] で rest を縮め、閉じたら固定 |
| タイムライン | 走らせながら再生、スクラブ | **ベイク必須**。再生中は計算しない |

規模は向こうが大きい(Rust 約1万行 + WGSL、Python・テスト込みで約5万行)。
同じ道で追いかけるより、**「型紙から服を作る」工程の質**で差を付けるのが筋。

## 2. Muslin にそのまま当てはまりそうな指摘(優先度高)

コードを読んで、向こうが実測で潰した問題と**同じ構造**が Muslin にあることを確認した。
症状はまだ Muslin 上で再現していない。

### 2.1 衝突後の緩和で縫い目が引き戻される

- **向こうの観察**: 自己衝突の後、距離制約だけを数回解き直す(Post-Relaxation)と、
  辺の長さを戻す力で縫い目の頂点が体の外側へ引かれ、**約10〜11mm の隙間が残った**。
  緩和の中で距離制約の直後に縫製制約も解くようにして、隙間が 0.00mm になった。
- **Muslin の現状**: `sim.rs` の `substep()` で、衝突解決の後の
  `post_collision_iterations` ループは `stretch_constraints` しか解いていない。
  `seam_constraints` は入っていない。
- **確かめ方**: 自己衝突 ON + コライダーあり、シームを閉じ切った状態で縫い目の
  頂点対の距離を測る。緩和に seam を足した版と比べる。

### 2.2 縫い目の頂点どうしが自己衝突で押し合う

- **向こうの観察**: 自己衝突は隣接する頂点(トポロジー上 2ホップ以内)を判定から外す。
  ところが縫い目を「1本の辺」と数えると、縫い目をまたぐ頂点は 3ホップ扱いになる。
  縫い目が閉じて布の厚みより近づいた瞬間、**別パーツの貫通と見なされて押し戻され**、
  縫製と自己衝突が綱引きになる。
- **向こうの対策**: 縫われた頂点対を Union-Find で1つの節点にまとめ(縫い目の横断を
  0ホップと数える)、その上で 2ホップの近傍表を作って除外に使う。
- **Muslin の現状**: `constrained_pairs` は「伸び制約の両端」と「曲げ制約の対角」だけ。
  **シームの頂点対は除外されていない**。しかも除外範囲は1ホップ相当。
  ROADMAP (2026-09-15) で、厚みが辺長の 0.8倍を超えると2つ隣どうしが押し合うことを
  実測済みで、これも同じ原因の別の現れ。
- **取り入れ方の候補**:
  1. 最小限: シームの対を `constrained_pairs` に足す
  2. 本命: 縫い目を縮約したグラフで 2ホップ近傍を初期化時に作り、除外に使う。
     頂点ごとにソートした CSR にすれば、判定は二分探索で済む(向こうは平均約20頂点/頂点)。
     「厚みは辺長の 0.4倍まで」という制限も緩められる可能性がある

### 2.3 縫い目を閉じ切った後に固定する

- 向こうは rest が目標に達し、距離が厚み以下になったら、その縫製制約のコンプライアンスを
  0 に固定する(`enable_sewing_lock`)。外力や衝突で縫い目が開き直るのを防ぐ。
- 開きっぱなしにしたいスリット用途のために OFF もできる。
- Muslin の `seam_closure = 1.0` 以降の振る舞いとして検討する価値がある。

### 2.4 縫う速さと縫う強さを分ける

- 向こうは「縮む速さ(`shrink_speed` m/s)」と「引く剛性(`sewing_stiffness`)」を分けている。
  布本体の張力に負けて縫い目が閉じ切らない問題への対策。
- Muslin は `Seam Close Frames`(時間)とシームのコンプライアンスを持っている。
  概念としては揃っているが、**フレーム数指定は長い縫い目と短い縫い目で閉じる速さが変わる**。
  長さに依存しない速さ指定を選べるようにするかは一考。

## 3. 衝突まわりの知見(中期)

### 3.1 衝突を反復ループの中で解く(Coupled XPBD)

- 反復を全部終えてから押し出すと、押し出された頂点の周りの辺が伸びたまま残り、
  重力で毎フレーム積み重なって**布がゴムのように伸びて垂れる**。
- 向こうはコライダーとの衝突を反復ループの各回に入れた(Macklin 2020 の考え方)。
  自己衝突は重いので、「後で緩和(既定)」と「反復の中で解く(高精度)」を選べる。
- 向こうの数字: 最大伸び率 9.55% → 緩和で 4.13%、反復内で 2.94%。
- Muslin は「衝突は反復の外 + 伸びだけの緩和2回」。
  まずコライダーとの衝突だけでも反復内に入れる実験をする価値がある(BVH 問い合わせの
  回数が反復数倍になるので、速度とのトレードオフを測る)。

### 3.2 頂点-頂点だけでは足りない

- 頂点-頂点の反発では、頂点が相手の三角形の真ん中を抜ける、辺どうしが交差する、を
  防げない。向こうは頂点-三角形 (最近点はボロノイ領域で求める) と
  辺-辺 (2線分の最近点 s, t を解析的に求める) を足した。
- Muslin の `resolve_self_collisions` のコメントでも同じ限界を認めている。
  自己衝突の質を上げる次の一手はこれ。

### 3.3 押し出しは相手側にも分ける(作用・反作用)

- 頂点 i が三角形 (a, b, c) に当たったら、i を押す分の反対向きを、重心座標と質量比で
  a, b, c にも分ける。辺-辺も (1-s, s) / (1-t, t) で分ける。これで運動量が保たれ、
  片側だけがめり込む非対称が消える。
- 向こうは GPU で競合を避けるために固定小数点の atomicAdd で蓄積している。
  CPU の Muslin では「蓄積してから一括適用」にすれば同じことが単純にできる。

### 3.4 候補ペアをサブステップ間で使い回す

- 空間ハッシュの構築と候補の列挙は**フレームの先頭サブステップだけ**で行い、
  後のサブステップはキャッシュしたペアだけを解く (I-Cloth 2018 の Active Pair Caching)。
- 取りこぼし対策: 集める範囲を「厚み + 頂点速度 × フレーム時間 × 1.3」に広げる。
  上限でクランプする。最終サブステップだけは作り直して全部解く(フレームの出力に
  貫通を残さない)。
- 向こうの数字では約1.8〜2.4倍の高速化。Muslin の自己衝突の時間内訳
  (`timings.hash_rebuild` など)を見て、ハッシュ構築の割合が大きければ効く。

### 3.5 遠い対は安く捨てる

- 頂点どうしの距離を1回測り、「厚み + (両頂点の周りの辺長の和) × 1.3」より遠ければ
  それ以降の判定をすべて飛ばす。向こうでは所要時間が半分になった。

## 4. 収束・品質の知見

### 4.1 Long Range Attachments (LRA)

- ピン留め頂点から各頂点までの布に沿った距離を初期化時に求めておき、
  それを超えないという不等式制約を最後に掛ける (Kim 2012)。
  重い生地や激しい動きで布が伸びて垂れるのを、1パスで防げる。
- 向こうは「検討中」で、まだ入れていない。Muslin のレザーやデニムで伸びが
  問題になるなら候補。Chebyshev とは役割が違う(Chebyshev は収束を速める、
  LRA は伸びの上限を決める)。

### 4.2 四角面の対角線の癖

- 四角面をどちらかの対角線で三角形に割ると、シワがその方向に寄る。
- 向こうの選択肢は3つ:
  - 十字分割: 中心に頂点を足して4三角形にする(等方的だが頂点が増える)
  - 動的対角線: 計算中は増やさず、止めたときにひずみの方向に沿って割る(既定)
  - 何もしない
- Muslin の `Fill Outline as Pattern` は三角形分割なので影響は小さいが、
  `Add Pattern Piece`(四角グリッド)を使う場合は同じ癖が出るはず。

### 4.3 ゴム紐(弾性グループ)

- 辺のグループごとに rest 長の倍率(0.7 なら 30% 縮む)と剛性の倍率を持たせる。
  ウエストや袖口のゴムを表現できる。
- 型紙で服を作る Muslin にとっては**機能として欲しいもの**。
  シームと同じ「エッジ選択で登録する」UI に乗せられる。

### 4.4 布の厚みを辺長から決める

- 向こうは用途ごと(標準 / スカート / 薄手)に、平均辺長の 2.5〜5% を厚みにし、
  **最短辺の 0.4倍**で上限を切っている。
- Muslin の `suggest_thickness`(辺長の 0.4倍)と同じ考え方で、上限の 0.4 という値も
  一致している。独立に同じ値に行き着いたのは裏付けとして記録しておく。

## 5. 却下された手法(向こうが実際に破綻を見たもの)

Muslin で同じ道を踏まないための一覧。

| 手法 | 何が起きたか | 代わりにやったこと |
|---|---|---|
| 相手の面の法線(表側)へ一律に押し戻す | 裏から当たった布や、めり込んだ布がさらに奥へ加速し、破綻が悪化した | 最近点への幾何学的な最短ベクトルで分離する |
| コライダーを抜けた頂点を法線方向へ即座に戻す | 球で突き上げると、布が風船のように膨らんだ | 最短距離と相対速度で分離し、裏抜けからの復帰はオプションにした |
| 連続衝突判定の押し戻しに緩和係数(0.2など)を掛ける | 必要な押し戻しの8割が消え、貫通したまま抜け出せなくなった | 近接の反発は緩めてよいが、貫通を止める押し戻しは100%掛ける |
| コライダーのモディファイアをすべて外して高速化 | Lattice や Curve で決まる形まで消え、見た目と判定がずれた | 頂点を増やす系(Subdivision など)だけを制限する |
| 平坦な場所(曲率の低い場所)の自己衝突判定を飛ばす | スカートの前身頃と後身頃のように、平らなまま近づく面がすり抜ける | 採用しない |
| GPU で count=0 の間接ディスパッチ | D3D12 / Vulkan でドライバが止まって画面が暗転した | 上限つきの直接ディスパッチ + シェーダー先頭で早期リターン(M4 の GPU 化で参照) |

注: 向こうには「頂点法線で外へ押し出す」`enable_normal_untangling`(既定 ON)があり、
1行目の却下理由と方向が似ている。どういう条件なら安全なのか、向こうの文書からは
読み取れなかった。Muslin で真似る場合はここを確かめること。

## 6. 取り入れない・鵜呑みにしないもの

- **ベイク必須の設計**: 向こうは、スクラブや逆再生で状態が壊れる例外処理に疲れて、
  再生中の計算をやめた。Muslin は再生しながら計算し、スクラブで元に戻す方向で
  既にテストを揃えている(決定性も担保している)。前提が違うので追従しない。
  ただし「ベイク後はパラメータをロックし、Free Bake で解除する」UI は参考になる。
- **ボーン別 SDF、動的な GPU 再ベイク、VRAM の自動調整**: GPU 前提の仕組み。
  M4(GPU化)まで保留。
- **「100%」「完全」という表現**: 向こうの文書には強い言い切りが多いが、根拠は
  自分たちのテストシーンでの実測。Muslin に持ち込むときは Muslin で測り直す。
- **性能の数字**: すべて RX 9070 XT + GPU 実装での値。CPU の Muslin には
  相対的な傾向(何倍速くなったか)しか参考にならない。

## 7. Muslin での次の一手(提案)

効果とコストの見込み順。どれも ROADMAP に載せる前に、実測で確かめる。

1. 衝突後の緩和に seam を足す(§2.1)。数行の変更で、測れば白黒つく
2. シームの頂点対を自己衝突の除外に足す(§2.2 の最小限版)
3. 縫い目を閉じ切った後の固定(§2.3)
4. 縫い目を縮約したグラフで 2ホップ除外(§2.2 の本命)。厚みの上限の実測もやり直す
5. コライダーとの衝突を反復の中へ(§3.1)
6. ゴム紐(§4.3)。機能として
7. 自己衝突に頂点-三角形と辺-辺を足し、押し出しを相手にも分ける(§3.2, §3.3)
